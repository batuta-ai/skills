# Plan — batuta-council: ask the council before approving a plan

## Decisions and context

Markdown only, agentskills.io format. Every persisted text is English; README.pt-BR.md mirrors README.md in Portuguese. Skills run on every host: no host-specific tool names (the lint's FORBIDDEN list), and the fan-out happens in core, never in the skill. Generated artefacts go to `.git/info/exclude`, never to `.gitignore`, which belongs to the user.

The engine is core `batuta council`, shipped in `v1.1.0-beta.51` (batuta-ai/core#163); its contract is `docs/council.md` in batuta-ai/core. Summary for the skill: `batuta council --plan <file> [--parallel N] [--timeout <duration>] [--out <dir>]`; counsellors are the `council` role rows of `.batuta/routing.md` or else the distinct non-self low/medium/high lane rows, the chairman is the `chairman` row or else the high lane row, at least two counsellors; three stages (independent critiques, anonymized cross-review with a ranking, chairman synthesis); artefacts `council.json` and `council.md` under `.batuta/councils/<date>-<plan slug>/`; exit 0 APPROVE, 2 REVISE (a result, not a failure), 4 INCOMPLETE (fewer than two critiques or cross-reviews parsed), 1 error before a report. The council never approves a plan; APPROVE is advice.

This plan was itself judged by `batuta council` on 2026-10-09 (REVISE); the accepted findings shaped the proofs above. Declined: fixture-driven scenario tests for the skill (a Markdown skill has no runtime; the lint is the test, and real integration is the smoke test after release). Outside this repository, in the host package with the vendoring: a `/batuta:council` command file and the opencode command, like the other skills.

**Task 1.** Follow the structure and tone of `skills/batuta-review/SKILL.md` (STOP lines, numbered procedure, *Done when*, a closing read-only sentence). The skill is read-only towards code and plans: it proposes edits to the plan and lets `batuta-plan` apply them after the maintainer agrees. On exit 4, it lists the failures from `council.md` and offers to rerun; it never treats INCOMPLETE as APPROVE. A credit to the design source, if any, names Andrej Karpathy's `llm-council` as design only, as core's `docs/council.md` does; run the lint after writing it.
